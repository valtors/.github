# Security Policy

## Reporting a vulnerability

Please report suspected vulnerabilities privately through GitHub's **Security** tab and **Report a vulnerability** flow on the affected repository.

Include:

- affected repository and version or commit;
- clear reproduction steps;
- expected impact;
- any suggested mitigation.

Do not open a public issue for an undisclosed vulnerability. If the private reporting button is unavailable, contact the organization owner through an existing trusted channel without including exploit details until a private channel is established. Do not include live credentials or unrelated personal data in a report.

## Scope

Security reports may include:

- unauthorized file, network, secret, or tool access;
- authentication or authorization bypass;
- prompt/tool injection with concrete security impact;
- unsafe agent execution or containment bypass;
- dependency or release-chain vulnerabilities with realistic impact;
- privacy failures, data exfiltration, or sensitive logging.

## Response expectations

We will acknowledge good-faith reports as capacity permits, investigate based on severity and exploitability, coordinate disclosure, and credit reporters who want attribution. This is a best-effort open-source project and does not promise a fixed response SLA.

## Safe harbor

Good-faith research that avoids privacy violations, service disruption, data destruction, persistence, and unnecessary access is welcome. Stop testing and report promptly if you encounter sensitive data.
