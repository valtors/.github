# Contributing to Valtors

Thank you for helping improve Valtors.

## Before you start

- Use an issue or Discussion to propose substantial features before implementation.
- Keep pull requests focused on one problem.
- Never include credentials, private data, proprietary code, or generated engagement.
- Respect third-party licenses and preserve required attribution.

## Development workflow

1. Fork or branch from the repository's default branch.
2. Read its `README.md`, `CONTRIBUTING.md`, `SECURITY.md`, and architecture notes.
3. Add a failing regression test before changing behavior.
4. Make the smallest implementation that passes the test.
5. Run the repository's formatter, linter, tests, and build.
6. Open a pull request describing the problem, solution, risks, and verification.

Repository-specific instructions override this default when they are more precise.

## AI-assisted contributions

AI-assisted work is welcome, but the submitter remains responsible for correctness, licensing, security, and review. Do not submit unreviewed generated code, bulk speculative changes, or fabricated test/benchmark results.

## Community channels

- Use Issues for reproducible bugs and accepted, scoped work.
- Use Discussions for questions, ideas, and design proposals.
- Follow `SECURITY.md` for vulnerabilities; never disclose them in a public issue.

By contributing, you agree that your contribution is licensed under the receiving repository's license.
